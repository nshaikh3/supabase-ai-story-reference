- Implemented local status/pause/resume/maintenance, dry-run/reviewed-digest orphan cleanup and pause/drain/recreate/verify worker rotation. Cleanup uses a permanent path claim and identity recheck before Storage API deletion; it never deletes managed object metadata through SQL. ## Failures and limitations

The first migration-creation attempt was blocked by filesystem sandbox permission on the CLI's local telemetry file; the authorized escalation created the migration. Negative target/flag checks deliberately failed. Non-failing terminal color and Node module-format warnings occurred. Browser generation emitted the previously observed Next destination-stream-closed diagnostic while its assertions passed; do not treat it as a security finding or silently remove it from the record. The new SVG rejection test initially expected different vendor error wording; it now asserts decoder rejection independently of platform wording, and passed with the full suite.

The initial hardening browser run passed five scenarios and failed two. Storage recovery incorrectly reused a retired path; the corrected test asserts reuse denial, then reserves a fresh path. Its pagination fixture now seeds historical stories for only a fresh synthetic identity through the guarded local operator, without changing production quotas or counters. Realtime landed on the sign-in page once; the failure did not reproduce in the focused rerun (two scenarios passed, 2.8 minutes, zero retries). Added credential-free session diagnostics for recurrence. Aggregate Auth diagnostics in that rerun showed successful requests; no application Auth cause is claimed to have been found or fixed.

Two ad-hoc preview probes needed correction: Next serialized its same-origin redirect as a relative Location, and native Fetch exposes status as a property rather than Playwright's method. The corrected probes passed; neither required an application change.

The full development dependency audit remains nonzero as described above. This local completion does not establish independent human security review, actual hosted CI, HTTPS/SMTP delivery, hosted resource limits, operational alert delivery, database/object backup restoration, paid Gemini behavior or suitability of generated content for children. No real child data should be used for the reference.

The CLI announced 2.120.0 during the October 7 advisor check. Its [release notes](https://github.com/supabase/cli/releases/tag/v2.120.0) were reviewed; this checkpoint retains the tested 2.119.0 runtime baseline. No claim that the CLI pin is the newest release is made.

Raw Storage transfer/re-upload bandwidth, Auth attempts, socket traffic and failed requests remain provider-owned traffic controls. Database issuance limits and application transform leases cannot replace those controls. Cleanup is eventual across services: a late upload may reappear on a permanently retired path until a future pass. Tombstones retain pseudonymous UUID metadata and need an explicit hosted retention/privacy decision.
